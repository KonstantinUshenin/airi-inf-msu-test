# Практическая работа

**Выход:** `.sh` или `.ipynb`.

Все задачи выполняются **на своей виртуальной машине, в домашнем каталоге**
(например, в `~/seminar-03/`). Каталог `/tmp` не используем: он вычищается при
перезагрузке, а результаты нужны вам до защиты. Скопируйте туда данные
семинара и работайте из этого каталога:

```bash
mkdir -p ~/seminar-03
cp -r ПУТЬ-К-РЕПОЗИТОРИЮ/seminars/03-unix-text/assets ~/seminar-03/
cd ~/seminar-03
```

Данные лежат в `assets/`: `students.csv`, `train.log`, `contacts.txt`,
`config-old.txt`, `config-new.txt` и каталог `project/`; пути в примерах относительные и
предполагают, что вы находитесь в `~/seminar-03`. Задачи решаются утилитами
`head`, `tail`, `wc`, `grep`, `find`, `sort`, `uniq`, `cut`, `tr`, `diff` и их
аналогами; `sed` и `awk` — тема отдельного занятия.

## База — 7 задач

### B1. Размер файла

**need:** `assets/train.log`.

Посчитайте, сколько в логе строк, слов и байт. Сохраните все три числа в `size.txt`.

**Пример:** `wc -l assets/train.log` → `19 assets/train.log`.

### B2. Начало и конец

**need:** `assets/train.log`.

Сохраните в `head-tail.txt` первые три и последние две строки лога.

**Пример:** последняя строка файла — `2026-09-01 10:25:21 INFO run finished id=exp-042 status=ok`.

### B3. Поиск ошибок

**need:** `assets/train.log`.

Сохраните в `errors.txt` строки со словом `ERROR` вместе с их номерами, а в `errors-count.txt` — только количество таких строк.

**Пример:** `grep -c ERROR assets/train.log` → `3`; первая найденная строка имеет номер `8`.

### B4. Всё, кроме обычных сообщений

**need:** `assets/train.log`.

Сохраните в `problems.txt` строки, в которых нет `INFO`, и допишите туда их количество.

**Пример:** таких строк `6` — три `WARN` и три `ERROR`.

### B5. Колонка CSV

**need:** `assets/students.csv`.

Получите отсортированный список групп без повторов и без строки заголовка. Сохраните в `groups.txt`.

**Пример:** три строки — `ML-01`, `ML-02`, `ML-03`.

### B6. Поиск файлов по имени

**need:** каталог `assets/project`.

Найдите в дереве все файлы `*.py` и сохраните отсортированный список путей в `python-files.txt`.

**Пример:** три пути, первый — `assets/project/src/model.py`.

### B7. Начало и конец строки

**need:** `assets/contacts.txt`.

Посчитайте, сколько строк начинается с фамилии `Иванов` и сколько заканчивается адресом на `example.org`. Точку в адресе нужно экранировать, иначе она совпадёт с любым символом.

**Пример:** `1` строка с начала и `3` строки с конца.

## Среднее — 7 задач

### M1. Лучшие результаты

**need:** `assets/students.csv`.

Отсортируйте студентов по убыванию балла и сохраните три верхние строки в `top3.txt`. Строка заголовка в результат попасть не должна.

**Пример:** первая строка — `Ksenia Morozova,ML-01,95`, третья — `Zhanna Belova,ML-03,88`.

### M2. Размер групп

**need:** `assets/students.csv`.

Посчитайте, сколько студентов в каждой группе, и отсортируйте результат по убыванию количества. Сохраните в `group-sizes.txt`.

**Пример:** сначала `4 ML-01`, затем `3 ML-02` и `3 ML-03` (`uniq -c` печатает число с отступом).

### M3. Значения loss

**need:** `assets/train.log`.

Извлеките из лога только числовые значения `loss`, без имени поля. Сохраните в `loss.txt` минимальное и максимальное значения.

**Пример:** всего значений `10`, минимум `0.7231`, максимум `2.4013`.

### M4. Различия конфигураций

**need:** `assets/config-old.txt`, `assets/config-new.txt`.

Сохраните различия в едином формате в `config.diff`, а в `config-summary.txt` — число добавленных и удалённых строк. Служебные заголовки `---` и `+++` считать не нужно.

**Пример:** добавлено `4` строки, удалено `3`; сама команда `diff` завершается кодом `1`.

### M5. Только в новой версии

**need:** `assets/config-old.txt`, `assets/config-new.txt`.

Сохраните в `only-new.txt` строки, которые есть в новом конфиге и отсутствуют в старом.

**Пример:** четыре строки, первая — `batch_size = 256`, последняя — `weight_decay = 0.05`.

### M6. TODO по дереву

**need:** каталог `assets/project`.

Найдите в дереве все строки с `TODO` вместе с путём и номером строки, отдельно — только в файлах `*.py`. Сохраните в `todo-all.txt` и `todo-python.txt`. Порядок обхода каталога не гарантирован, поэтому результат отсортируйте.

**Пример:** всего `3` совпадения, в `*.py` — `2`; первая строка `todo-python.txt` — `assets/project/src/model.py:9:        # TODO: заменить заглушку настоящим слоем`.

### M7. Номера паспортов

**need:** `assets/contacts.txt`.

В выгрузке номер записан двумя способами: `4509 123456` и `45 09 654321`. Одним расширенным регулярным выражением вытащите только номера (без фамилий и телефонов), сохраните их в `passports.txt` и отдельно выведите строки, где паспорта нет.

**Пример:** найдено `5` номеров; без паспорта — одна строка, `Белова Жанна`.

## Сложное — 6 задач

### H1. Отчёт по логу

**need:** `assets/train.log`.

Напишите `log-report.sh`, который принимает путь к логу и печатает четыре строки: число строк, число ошибок, число предупреждений и номер последней эпохи. Отсутствие ошибок не должно ломать скрипт.

**Пример:** `./log-report.sh assets/train.log` → `lines=19`, `errors=3`, `warnings=3`, `last_epoch=10`.

### H2. Топ-N групп

**need:** `assets/students.csv`.

Напишите `top-groups.sh`, который принимает путь к CSV и число `N` и печатает `N` самых многочисленных групп. При равном количестве студентов порядок должен быть предсказуемым, а не случайным.

**Пример:** `./top-groups.sh assets/students.csv 2` → `4 ML-01` и `3 ML-02`.

### H3. Проверка CSV

**need:** `assets/students.csv`; копия этого файла с одной сломанной строкой.

Напишите `check-csv.sh`. Если в каждой строке ровно три поля — пустой вывод и код `0`. Иначе — номера и текст плохих строк и ненулевой код.

**Пример:** на `assets/students.csv` → пустой вывод, код `0`. На копии с дописанной строкой `Pavel Rybakov,ML-02` → вывод `12:Pavel Rybakov,ML-02` и код `1`.

### H4. Имена с пробелами

**need:** каталог `assets/project` (содержит файл `old data.csv`).

Посчитайте суммарное число строк во всех файлах `*.csv` дерева так, чтобы имя с пробелом обработалось правильно, и сохраните итог в `csv-lines.txt`. В `unsafe.txt` сохраните ошибку наивного варианта, в котором имя разбивается на части.

**Пример:** правильный итог — `9 total`. Наивный вариант ищет несуществующие `assets/project/data/old` и `data.csv`, сообщает `No such file or directory` и печатает итог `7`.

### H5. Частотный словарь

**need:** `assets/train.log`.

Постройте частотный словарь лога: словом считается последовательность букв, регистр не учитывается. Сохраните пять самых частых слов вместе с количеством в `top-words.txt`. При равных частотах порядок должен быть предсказуемым.

**Пример:** первая строка — `13 info`, далее `10 acc`, `10 epoch`, `10 loss`, `3 error` (`uniq -c` печатает число с отступом).

### H6. `grep` и `ripgrep`

**need:** `ripgrep`; копия каталога `assets/project`.

Сравните поиск `TODO` через `grep -rn` и `rg -n`: сохраните оба отсортированных вывода и убедитесь, что они совпадают. Затем добавьте в копию дерева скрытый файл с `TODO` и объясните расхождение. Добейтесь, чтобы `rg` нашёл ту же строку, что и `grep`.

**Пример:** на исходном дереве оба инструмента дают `3` совпадения. После добавления скрытого файла `grep -rn` находит `4`, `rg -n` — по-прежнему `3`, а `rg -n --hidden` — `4`.
