# Семинар 7. Unix-terminal. Работа с сетью

## Цель

Научиться диагностировать сетевое окружение, проверять доступность хостов и сервисов, анализировать DNS-записи, управлять межсетевым экраном и передавать данные по сети из терминала. Результаты фиксировать в отчёте, артефакты (скрипты, выводы команд, скриншоты) сохранять на диске.

## Теоретический минимум

- **Сетевой интерфейс и IP-адрес:** интерфейсы (eth0, wlan0, lo), IPv4/IPv6, маска подсети, шлюз по умолчанию; `ifconfig` (устаревший) и `ip addr` (современный аналог).
- **Порты и сокеты:** TCP/UDP-порт, тройка (протокол, адрес, порт); привилегированные порты (< 1024), эфемерные порты.
- **DNS:** иерархия доменных имён, типы записей (A, AAAA, MX, NS, CNAME, TXT), рекурсивный и авторитативный запрос; утилиты `nslookup` и `dig`.
- **ICMP и ping:** назначение протокола ICMP, TTL, RTT; почему некоторые хосты не отвечают на ping.
- **WHOIS:** реестры доменных имён и IP-адресов (IANA, RIPE, ARIN); что можно узнать о домене или IP-блоке.
- **Межсетевой экран (firewall):** цепочки INPUT/OUTPUT/FORWARD, политика по умолчанию (ACCEPT/DROP); `ufw` как фронтенд к iptables/nftables.
- **Мониторинг соединений:** `netstat` (устаревший) и `ss` (современный): состояния TCP (LISTEN, ESTABLISHED, TIME_WAIT), фильтрация по порту/протоколу.
- **Netcat (`nc`):** «швейцарский нож» сети — режимы: клиент, слушающий сервер, сканер портов, передача файлов.
- **Загрузка данных:** `wget` (рекурсивная загрузка, зеркалирование) vs `curl` (гибкие запросы, поддержка множества протоколов, работа с API).

## Задачи

1. **Сетевые интерфейсы и адресация**
   - Вывести список сетевых интерфейсов и их IP-адресов с помощью `ifconfig` (или `ip addr show`).
   - Определить: какой интерфейс используется для выхода в интернет, какой IP-адрес назначен, какая маска подсети.
   - Вывести маршрут по умолчанию: `ip route` (или `route -n`); записать адрес шлюза.
   - Сравнить вывод `ifconfig` и `ip addr` — описать в отчёте, чем отличаются и почему `ifconfig` считается устаревшим.

2. **Проверка доступности хостов (ping)**
   - Выполнить `ping` до нескольких хостов: `8.8.8.8` (Google DNS), `ya.ru`, `127.0.0.1`.
   - Ограничить число пакетов (`-c 5`); зафиксировать RTT (min/avg/max) и процент потерь.
   - Попробовать `ping` до хоста, который не отвечает (например, `ping -c 3 -W 2 192.0.2.1`); объяснить в отчёте возможные причины (firewall, фильтрация ICMP, хост не существует).

3. **DNS-запросы (nslookup, dig)**
   - С помощью `nslookup` определить IP-адрес для `msu.ru` и `github.com`.
   - С помощью `dig` получить записи разных типов для домена по выбору: `dig A msu.ru`, `dig MX msu.ru`, `dig NS msu.ru`, `dig TXT msu.ru`.
   - Выполнить обратный DNS-запрос: `dig -x <IP-адрес>` (например, для `8.8.8.8`); объяснить результат.
   - Сравнить вывод `nslookup` и `dig` — записать в отчёте, какой инструмент даёт больше информации и почему `dig` предпочтительнее.

4. **WHOIS**
   - Выполнить `whois msu.ru` — определить регистратора, дату регистрации, серверы имён.
   - Выполнить `whois 8.8.8.8` — определить, кому принадлежит IP-блок.
   - Кратко описать в отчёте, для каких задач полезен WHOIS (администрирование, безопасность, расследование инцидентов).

5. **Мониторинг соединений (netstat, ss)**
   - Вывести все слушающие TCP-порты: `ss -tlnp` (или `netstat -tlnp`).
   - Определить, какие сервисы слушают на привилегированных портах (< 1024); записать имя процесса и порт.
   - Вывести все установленные TCP-соединения: `ss -tnp`; найти соединение с известным сервисом (например, SSH-сессия).
   - Выполнить `ss -s` — вывести статистику по сокетам; кратко описать, что означают числа.

6. **Межсетевой экран (ufw)**
   - Проверить статус `ufw`: `sudo ufw status verbose`.
   - Добавить правило: разрешить входящие на порт 8080/tcp (`sudo ufw allow 8080/tcp`).
   - Вывести список правил: `sudo ufw status numbered`.
   - Удалить добавленное правило (`sudo ufw delete <номер>`).
   - Описать в отчёте: что произойдёт, если включить `ufw` с политикой по умолчанию `deny` и не добавить правило для SSH.

7. **Netcat (nc): клиент-сервер и передача данных**
   - Запустить слушающий сервер на одном терминале: `nc -l -p 9999` (или `nc -l 9999` в зависимости от версии).
   - Подключиться с другого терминала: `nc localhost 9999`; отправить несколько текстовых сообщений; зафиксировать вывод на обоих концах.
   - Передать файл через `nc`: на стороне приёмника `nc -l -p 9999 > received.txt`, на стороне отправителя `nc localhost 9999 < original.txt`; проверить целостность файла (`md5sum` или `sha256sum`).
   - Использовать `nc` как простой сканер портов: `nc -zv localhost 22 80 443 8080` — записать, какие порты открыты.

8. **Загрузка данных: wget и curl**
   - Скачать веб-страницу с помощью `wget`: `wget https://example.com` — посмотреть сохранённый файл.
   - Скачать файл с помощью `curl`: `curl -O <URL-файла>` (например, небольшой файл с GitHub).
   - Выполнить HTTP-запрос с выводом заголовков: `curl -I https://httpbin.org/get`; описать в отчёте основные заголовки ответа (Content-Type, Server, Date).
   - Отправить POST-запрос: `curl -X POST -d '{"key":"value"}' -H 'Content-Type: application/json' https://httpbin.org/post`; зафиксировать ответ.
   - Сравнить `wget` и `curl` в отчёте: типичные сценарии использования, ключевые отличия.

9. **Сетевая диагностика: комплексное задание**
   - Написать bash-скрипт `netdiag.sh`, который:
     - выводит IP-адрес и маску основного интерфейса;
     - выводит шлюз по умолчанию;
     - выполняет `ping -c 3` до шлюза и до `8.8.8.8`;
     - выполняет `dig A ya.ru` и выводит IP-адрес;
     - выводит количество установленных TCP-соединений (`ss -tn | wc -l`);
     - сохраняет весь вывод в файл `netdiag_report.txt`.
   - Запустить скрипт, сохранить `netdiag.sh` и `netdiag_report.txt` в артефакты.

10. **Сканирование портов и «непингуемый» сервер**
   - Преподаватель выдаёт адрес сервера, который **не отвечает на ping** (ICMP заблокирован файрволом).
   - Выполнить `ping -c 3 <адрес>` — убедиться, что ответа нет (100% packet loss).
   - Проверить доступность с помощью `nc -zv <адрес> 80` и `nc -zv <адрес> 443` — зафиксировать, какие порты отвечают.
   - Выполнить HTTP-запрос к серверу: `curl -I http://<адрес>` (или `https://`); убедиться, что сервер работает и отдаёт HTTP-ответ.
   - Установить `nmap` (если ещё не установлен) и просканировать сервер: `nmap -Pn -p 22,80,443,8080,8443 <адрес>` (флаг `-Pn` пропускает ping-проверку и сканирует даже «недоступные» хосты).
   - Сравнить результаты `ping`, `nc` и `nmap` — записать в отчёт таблицу: инструмент, результат, вывод.
   - Ответить в отчёте на вопросы:
     - Почему нельзя делать вывод о недоступности сервера только по результатам `ping`?
     - Какой протокол использует `ping` и почему его часто блокируют на серверах?
     - В каких ситуациях администраторы намеренно отключают ответ на ICMP?

Отчёт и артефакты (скрипты, выводы команд, скриншоты) хранить в репозитории семинара или в Jupyter-ноутбуке / на удалённом сервере по указанию преподавателя.

## Бонусные задачи

- **Traceroute и анализ маршрута:** выполнить `traceroute` (или `mtr`) до нескольких хостов (например, `msu.ru`, `github.com`, IP-адрес в другой стране); описать в отчёте, через какие автономные системы (AS) проходит маршрут, используя `whois` для промежуточных IP.
- **Простой HTTP-сервер и curl:** запустить `python3 -m http.server 8080` в каталоге с файлами; с другого терминала загрузить файл через `curl http://localhost:8080/filename`; добавить правило `ufw` (или аналог) для разрешения доступа к порту 8080 извне и проверить доступность с другой машины (или описать, как это сделать).
- **Сканирование портов с nmap:** установить `nmap` и выполнить сканирование localhost (`nmap -sT localhost`); описать обнаруженные открытые порты и сопоставить с выводом `ss -tlnp`; объяснить разницу между SYN-сканированием (`-sS`) и connect-сканированием (`-sT`).
