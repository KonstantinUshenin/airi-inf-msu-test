# Практическая работа

**Выход:** `.py` или `.ipynb`.

**Данные:** `python3 assets/make_data.py` создаёт каталог `data/` с учебными
файлами. Содержимое фиксировано, поэтому числа в тестовых примерах совпадают у
всех. Пути в задачах указаны относительно каталога, где лежит `data/`.

## База — 6 задач

### B1. Символы и байты

**need:** нет.

Закодируйте строку `Отчёт готов` в `utf-8` и в `cp1251`. Выведите число символов
в строке и число байт в каждой кодировке. Объясните разницу в комментарии.

**Пример:** символов `11`, байт в utf-8 — `21`, байт в cp1251 — `11`.

### B2. Кракозябры

**need:** нет.

Получите из строки `Модель обучена` «кракозябры»: закодируйте её в `utf-8`, а
декодируйте как `cp1251`. Затем обратной операцией восстановите исходный текст из
испорченной строки.

**Пример:** `Модель обучена` → `РњРѕРґРµР»СЊ РѕР±СѓС‡РµРЅР°` → `Модель обучена`.

### B3. Файл в чужой кодировке

**need:** `data/report-cp1251.txt`.

Прочитайте файл тремя способами: как `utf-8` (исключение перехватите и выведите
его текст), как `utf-8` с `errors="replace"` и как `cp1251`. Выведите первую
строку файла для второго и третьего способа.

**Пример:** первый способ печатает `'utf-8' codec can't decode byte 0xce ...`;
второй — строку из символов-заменителей `�` (по одному на каждую неразобранную
последовательность; здесь каждый нечитаемый байт плох сам по себе, а пробелы
остаются на месте): `����� �� ������������`; третий —
`Отчёт по эксперименту`.

### B4. Разбор строки методами str

**need:** нет.

Без регулярных выражений разберите строку
`2026-11-03 12:04:12 INFO epoch=1 loss=0.7100 acc=0.6210`: получите отдельно дату
(только `2026-11-03`, без времени), уровень и словарь из пар `ключ=значение`.
Используйте `split` и `partition`.

**Пример:** `2026-11-03`, `INFO`,
`{'epoch': '1', 'loss': '0.7100', 'acc': '0.6210'}`.

### B5. Файлы по маске

**need:** `data/runs/`.

Найдите рекурсивно все файлы `metrics.csv` внутри `data/runs`. Выведите их
количество и отсортированный список путей относительно `data/runs`.

**Пример:** найдено `3`, первый в списке — `archive/run-03/metrics.csv`.

### B6. Первая регулярка

**need:** нет.

Регулярным выражением найдите в строке из B4 все числа с дробной частью. Дата и
время в результат попасть не должны.

**Пример:** `['0.7100', '0.6210']`.

## Среднее — 6 задач

### M1. Файл с BOM

**need:** `data/excel-bom.csv`.

Прочитайте файл как `utf-8` и как `utf-8-sig`. В обоих случаях выведите `repr`
имени первой колонки. Комментарием укажите, какой способ верный и почему.

**Пример:** `'\ufeffepoch'` для `utf-8` и `'epoch'` для `utf-8-sig`.

### M2. Нормализация имён файлов

**need:** `data/names/`.

Для каждого файла с расширением `.csv` в `data/names` постройте нормализованное
имя: без расширения, в нижнем регистре, дефисы заменены на подчёркивания. Файлы с
другим расширением пропустите. Отдельно покажите на имени `metrics.csv`, что
`strip(".csv")` для снятия расширения не годится.

**Пример:** `RUN-05_2026-11-05.csv` → `run_05_2026_11_05`; обработано `5` файлов;
`"metrics.csv".strip(".csv")` даёт `metri`, а не `metrics`.

### M3. Обход дерева запусков

**need:** `data/runs/`.

Найдите все файлы `train.log` внутри `data/runs`. Для каждого выведите имя
запуска (имя каталога, в котором лежит файл) и число строк в файле. Порядок вывода
— по имени запуска.

**Пример:** `run-01 2`, `run-02 2`, `run-03 2`.

### M4. Именованные группы

**need:** `data/train.log`.

Разберите регулярным выражением с именованными группами строки лога вида
`<время> <уровень> epoch=<n> loss=<x> acc=<y>`. Выведите список словарей
`groupdict()` и число распознанных строк.

**Пример:** распознано `4`, первый словарь —
`{'time': '2026-11-03 12:04:12', 'level': 'INFO', 'epoch': '1', 'loss': '0.7100', 'acc': '0.6210'}`.

### M5. Маскирование секретов

**need:** `data/train.log`.

Замените в логе значения полей `user=` и `token=` на `***`, сохраните результат в
`data/train-safe.log`. Имена полей должны остаться на месте, остальные строки — не
измениться.

**Пример:** последняя строка становится
`2026-11-03 12:30:00 INFO run finished user=*** token=***`.

### M6. Счётчик уровней

**need:** `data/train.log`.

Посчитайте регулярным выражением, сколько строк лога относится к каждому уровню
(`INFO`, `WARNING`, `ERROR`). Строки продолжения (traceback) уровня не имеют и в
подсчёт попадать не должны.

**Пример:** `INFO 7`, `WARNING 1`, `ERROR 1`.

## Сложное — 6 задач

### H1. Парсер лога в csv

**need:** `data/train.log`.

Соберите из лога таблицу `epoch,loss,acc` и сохраните её в `data/metrics.csv` с
заголовком. Отдельно выведите число строк, которые не удалось разобрать, и первую
из них.

**Пример:** в csv `4` строки данных, нераспознанных — `9`, первая из них
`2026-11-03 12:00:01 INFO run started model=resnet18 batch_size=64`.

### H2. Многострочная запись

**need:** `data/train.log`.

Сгруппируйте строки лога в записи: новая запись начинается со строки, которая
начинается с даты, остальные строки (traceback) приклеиваются к предыдущей.
Выведите число записей и целиком ту запись, где встретился уровень `ERROR`.

**Пример:** записей `9`; запись с `ERROR` состоит из `5` строк и заканчивается
`OSError: No space left on device`.

### H3. Определение кодировки

**need:** `data/report-cp1251.txt`, `data/train.log`.

Напишите функцию, которая по пути к файлу возвращает пару «кодировка, текст»:
сначала пробуется `utf-8`, при `UnicodeDecodeError` — `cp1251`. Проверьте её на
обоих файлах. Комментарием ответьте, почему тем же приёмом нельзя отличить
`cp1251` от `koi8-r`.

**Пример:** `data/report-cp1251.txt` → `cp1251`, `data/train.log` → `utf-8`.

### H4. Лучший запуск

**need:** `data/runs/`.

По всем файлам `train.log` в `data/runs` соберите минимальное значение `loss`
каждого запуска. Выведите строки вида «запуск — минимальный loss», отсортированные
по возрастанию loss, и отдельно назовите лучший запуск.

Подсказка: сортировать надо не по имени запуска, а по значению — у `sorted` и
`min` для этого есть аргумент `key` (см. документацию, «Sorting Techniques»).

**Пример:** лучший — `run-02` со значением `0.2500`.

### H5. Проверка соглашения об именах

**need:** `data/names/`.

Проверьте имена файлов в `data/names` на соответствие шаблону
`run-NN_YYYY-MM-DD.csv`, где `NN` — ровно две цифры, а дата — четыре цифры, месяц и
день по две. Выведите отдельно подходящие имена и нарушителей. Используйте
`fullmatch`.

**Пример:** подходят `2` имени, нарушителей `4`, среди них
`run-04_03-11-2026.csv`.

### H6. Пары ключ=значение с кавычками

**need:** нет.

Разберите в словарь строку
`model="resnet 18" batch_size=64 note="loss=nan on 17"`. Значение может быть либо
в двойных кавычках и содержать пробелы и знак `=`, либо идти без кавычек до
первого пробела. Кавычки в результат попадать не должны.

Подсказка: пригодятся альтернатива `a|b` и не-захватывающая группа `(?:...)` из
раздела 4 демки, а также отрицающий класс `[^"]` — про него см. документацию
`re`, раздел «Regular Expression Syntax».

**Пример:**
`{'model': 'resnet 18', 'batch_size': '64', 'note': 'loss=nan on 17'}`.
