# Практическая работа

**Выход:** `.py` или `.ipynb`.

**Данные:** `python3 assets/make_data.py` создаёт каталог `data/` с учебной
выгрузкой экспериментов. Содержимое фиксировано, поэтому числа в тестовых
примерах совпадают у всех. Пути в задачах указаны относительно каталога, где
лежит `data/`.

| Файл | Что внутри |
|---|---|
| `data/runs.csv` | 14 запусков обучения: модель, датасет, гиперпараметры, `val_acc`, время, GPU, статус |
| `data/models.csv` | справочник моделей: семейство и число параметров (неполный) |
| `data/epochs.csv` | метрики по эпохам для четырёх запусков |
| `data/notes.csv` | комментарии инженера; выгрузка в кодировке **cp1251** |

Проверено на pandas 3.0.5 и polars 1.43.2. Числа в примерах приведены так, как их
печатает pandas: `mean` — без округления, если в задаче не сказано иначе.

## База — 6 задач

### B1. Первый взгляд на выгрузку

**need:** `data/runs.csv`.

Прочитайте `data/runs.csv` в `DataFrame`. Выведите размер таблицы, типы столбцов
и первые три строки. В комментарии ответьте, почему у `batch_size` тип `int64`, а
у `val_acc` — `float64`.

**Пример:** размер `(14, 10)`; `val_acc` → `float64`, `model` → `str`; первая
строка — запуск `r01` модели `resnet18` на `cifar10`.

### B2. Сводка по числовым столбцам

**need:** `data/runs.csv`.

Выведите `describe()` по таблице. Назовите столбец, у которого `count` меньше
числа строк, и объясните в комментарии, что это значит.

**Пример:** у всех числовых столбцов `count` равен `14.000000`, и только у
`val_acc` — `12.000000`; максимум `train_min` — `90.000000`.

### B3. Отбор по условию

**need:** `data/runs.csv`.

Выведите `run_id`, `model` и `val_acc` тех запусков, которые считались на
датасете `cifar10` и дали точность строго выше `0.9`. Условия объедините в одну
маску.

**Пример:** пять строк, список `run_id` — `['r02', 'r04', 'r05', 'r07', 'r08']`.

### B4. Где пропуски

**need:** `data/runs.csv`.

Посчитайте число пропусков в каждом столбце. Отдельно выведите `run_id` запусков
без `val_acc` и `run_id` запусков без `gpu`. В комментарии объясните, почему
пропуск в `val_acc` нельзя заменить нулём.

**Пример:** пропуски есть только в `val_acc` (`2`) и `gpu` (`1`); без `val_acc` —
`['r06', 'r14']`, без `gpu` — `['r11']`.

### B5. Топ-3 запуска

**need:** `data/runs.csv`.

Выведите три запуска с наибольшей `val_acc`: `run_id`, `model`, `val_acc`.

**Пример:**

```
  run_id      model  val_acc
7    r08  vit_small    0.931
6    r07  vit_small    0.924
3    r04   resnet50    0.915
```

### B6. Файл в чужой кодировке

**need:** `data/notes.csv`.

Файл с комментариями выгружен в кодировке cp1251. Прочитайте его в `DataFrame`,
выведите размер и комментарий к запуску `r06`. В комментарии к коду объясните,
почему этот файл нельзя разобрать через `split(",")`.

**Пример:** размер `(4, 2)`; комментарий к `r06` —
`Разошлось на первой эпохе, lr слишком большой`.

## Среднее — 6 задач

### M1. loc против iloc

**need:** `data/runs.csv`.

Отберите запуски на датасете `imagenette`. Выведите список меток индекса
получившейся таблицы, `run_id` её первой строки через `iloc` и результат
обращения `.loc[0]` (`KeyError` перехватите и напечатайте). Объясните в
комментарии, почему `.loc[0]` не работает.

**Пример:** индекс `[8, 9, 10, 12, 13]`; `iloc[0]` даёт `r09`; `.loc[0]` →
`KeyError: 0`.

### M2. Присваивание, которое не работает

**need:** `data/runs.csv`.

Замените пропущенное имя GPU на строку `unknown` двумя способами: сначала через
цепочку `df[маска]["gpu"] = "unknown"`, затем через `.loc[маска, "gpu"]`. После
каждого способа выведите `value_counts(dropna=False)` по столбцу `gpu` и
объясните в комментарии разницу.

**Пример:** после цепочки — `a100 9`, `h100 4`, `NaN 1` (ничего не изменилось,
выведено предупреждение `ChainedAssignmentError`); после `.loc` — `a100 9`,
`h100 4`, `unknown 1`.

### M3. Отчёт по моделям

**need:** `data/runs.csv`.

Постройте таблицу по моделям: число запусков `n`, число запусков с посчитанной
метрикой `scored`, средняя `mean_acc`, максимальная `best_acc` и суммарное время
`total_min`. Средние округлите до четырёх знаков. Объясните в комментарии, почему
`n` и `scored` различаются.

**Пример:**

```
              n  scored  mean_acc  best_acc  total_min
model
mobilenet_v3  2       2    0.8095     0.848       24.0
resnet18      4       4    0.8680     0.901       63.3
resnet50      4       3    0.8873     0.915      151.8
vit_small     4       3    0.9050     0.931      265.5
```

### M4. Датасет против модели

**need:** `data/runs.csv`.

Посчитайте среднюю `val_acc` отдельно по датасетам и отдельно по парам
«датасет + модель». Округлите до четырёх знаков. В комментарии ответьте, какой
датасет сложнее.

**Пример:** `cifar10` → `0.8979`, `imagenette` → `0.8212`; для пары
`('imagenette', 'mobilenet_v3')` — `0.7710`.

### M5. Склейка со справочником

**need:** `data/runs.csv`, `data/models.csv`.

Присоедините к запускам справочник моделей так, чтобы **ни один запуск не
потерялся**. Выведите размер результата, число строк без `family`, их `run_id` и
среднюю точность по семействам (`count` и `mean`, округление до четырёх знаков).

**Пример:** размер `(14, 12)`; без `family` — `2` строки, `['r12', 'r13']`;
`cnn` → `count 7`, `mean 0.8763`; `transformer` → `count 3`, `mean 0.9050`.

### M6. Свод по эпохам

**need:** `data/epochs.csv`.

По таблице эпох посчитайте для каждого запуска: число эпох, минимальный
`train_loss` и максимальную `val_acc`.

**Пример:**

```
        n_epochs  min_loss  best_acc
run_id

r02            5      0.51     0.901
r04            5      0.49     0.915

```

## Сложное — 6 задач

### H1. Сводный отчёт «датасет × семейство»

**need:** `data/runs.csv`, `data/models.csv`.

Постройте отчёт по парам «датасет + семейство моделей»: число запусков `n`,
средняя `mean_acc` (округление до четырёх знаков) и суммарное `total_min`.
Модели, которых нет в справочнике, должны попасть в отчёт отдельной категорией
`unknown`, а не исчезнуть. Ключи группировки верните обычными столбцами.

**Пример:** шесть строк; `('cifar10', 'cnn')` → `n 6`, `mean_acc 0.8960`,
`total_min 130.1`; `('imagenette', 'unknown')` → `n 1`, `mean_acc 0.7710`,
`total_min 16.0`.

### H2. Лучшая эпоха каждого запуска

**need:** `data/epochs.csv`, `data/runs.csv`.

Для каждого запуска из `data/epochs.csv` найдите строку с максимальной `val_acc`
(номер эпохи и значение). Присоедините итоговую `val_acc` из `data/runs.csv` и
столбцом `same` покажите, совпадают ли они. Последнюю строку каждого запуска
брать нельзя — максимум не всегда на последней эпохе.

**Пример:** четыре строки; `r01` → эпоха `4`, `0.872`, `same True`; `r02` →
эпоха `5`, `0.901`, `same True`. Все четыре значения `same` равны `True`.

### H3. Какой learning rate лучше

**need:** `data/runs.csv`.

Для каждой пары «модель + lr» посчитайте среднюю `val_acc`, отбросьте пары без
метрики и выведите таблицу, отсортированную по модели и по убыванию точности.
Отдельно выведите лучший `lr` для каждой модели.

**Пример:** в общей таблице восемь строк; лучшие пары — `mobilenet_v3` с
`lr 0.0100` (`0.8095`), `resnet18` с `lr 0.0010` (`0.8840`), `resnet50` с
`lr 0.0010` (`0.9080`), `vit_small` с `lr 0.0003` (`0.9310`).

### H4. Цена неудачных запусков

**need:** `data/runs.csv`.

Посчитайте суммарное время всех запусков, время запусков со статусом, отличным от
`ok`, и их долю от общего времени в процентах (округление до двух знаков).
Выведите `run_id`, `status` и `train_min` неудачных запусков.

**Пример:** всего `504.6` минут, потрачено впустую `119.7` (`23.72` %);
неудачные — `r06` (`diverged`, `29.7`) и `r14` (`oom`, `90.0`).

### H5. Комментарии к запускам

**need:** `data/runs.csv`, `data/notes.csv`.

Присоедините комментарии (файл в cp1251) к таблице запусков, не потеряв ни одного
запуска. С помощью `indicator=True` покажите, сколько строк получило комментарий,
а сколько осталось без него. Выведите все запуски с комментарием: `run_id`,
`status`, `comment`.

**Пример:** `left_only 10`, `both 4`, `right_only 0`; с комментариями — `r06`,
`r08`, `r11`, `r14`.

### H6. Тот же вопрос в polars

**need:** `data/runs.csv`.

Ленивым запросом polars (`scan_csv` → … → `collect`) посчитайте по успешным
(`status == "ok"`) запускам число запусков и среднюю `val_acc` для каждой модели,
округлив до четырёх знаков, и отсортируйте по убыванию средней точности. Выведите
план запроса (`explain()`) и результат. В комментарии объясните, что в плане
означают строки `PROJECT` и `SELECTION`.

**Пример:** в плане `PROJECT 3/10 COLUMNS` и `SELECTION: col("status") == "ok"`;
первая строка результата — `vit_small`, `n 3`, `mean_acc 0.905`; последняя —
`mobilenet_v3`, `n 2`, `mean_acc 0.8095`.
