# Семинар 2. Unix-terminal. Работа с файлами

## Цель

Научиться подключаться к удалённому серверу по SSH, уверенно работать в командной оболочке bash: навигация по файловой системе, создание и перемещение файлов, управление правами доступа, перенаправление потоков ввода-вывода, использование переменных окружения, управление процессами и мониторинг ресурсов. Все результаты фиксировать в отчёте, артефакты (скрипты, выводы команд) сохранять на диске.

## Теоретический минимум

- **SSH (Secure Shell):** протокол для безопасного удалённого подключения к серверу; аутентификация по паролю или по ключу (`ssh user@host`).
- **bash:** командная оболочка (shell) — интерпретатор команд; читает команды из stdin или из скрипта, запускает программы, поддерживает переменные, условия, циклы.
- **Файловая система Unix:** иерархическое дерево с корнем `/`; всё есть файл (обычные файлы, каталоги, символические ссылки, устройства).
- **Права доступа:** три категории (owner, group, others) × три бита (read, write, execute); числовая (`chmod 755`) и символьная (`chmod u+x`) нотация; владелец и группа (`chown`).
- **Стандартные потоки:** stdin (fd 0), stdout (fd 1), stderr (fd 2); перенаправление (`>`, `>>`, `2>`, `2>&1`, `<`) и конвейер (`|`).
- **Переменные окружения:** пары ключ=значение, наследуемые дочерними процессами; `export`, `env`, важные переменные: `PATH`, `HOME`, `USER`, `SHELL`.
- **Сигналы и управление заданиями:** `Ctrl+C` посылает SIGINT (прервать), `Ctrl+Z` — SIGTSTP (приостановить); `bg`, `fg`, `jobs`, `&` для фоновых задач.
- **Процессы:** каждая запущенная программа — процесс с PID; `ps` — снимок процессов, `top`/`htop` — мониторинг в реальном времени.
- **Информация о системе:** `uname -a` — ядро и архитектура; `/etc/os-release` — дистрибутив и версия; `nvidia-smi` — GPU (если есть).

## Задачи

1. **SSH-подключение и ориентация на сервере**
   - Подключиться к учебному серверу по SSH: `ssh <user>@<host>`. Зафиксировать в отчёте команду подключения.
   - Узнать, кто вы и где находитесь: выполнить `whoami`, `hostname`, `pwd`. Записать результаты.
   - Вывести информацию о системе: `uname -a` и `cat /etc/os-release`. Определить дистрибутив, версию ядра и архитектуру процессора.
   - Сохранить вывод команд в файл: `uname -a > ~/system_info.txt && cat /etc/os-release >> ~/system_info.txt`. Убедиться, что файл содержит обе записи (`cat ~/system_info.txt`).

2. **Навигация по файловой системе**
   - Перейти в корневой каталог (`cd /`) и вывести его содержимое (`ls`). Кратко описать в отчёте назначение каталогов `/bin`, `/etc`, `/home`, `/tmp`, `/var`.
   - Вернуться в домашний каталог тремя способами: `cd`, `cd ~`, `cd $HOME`. Убедиться с помощью `pwd`, что результат одинаков.
   - Создать структуру каталогов для работы: `mkdir -p ~/seminar02/data ~/seminar02/scripts ~/seminar02/reports`. Проверить результат с помощью `ls -R ~/seminar02` или `tree ~/seminar02` (если установлен).
   - Перейти в `~/seminar02` и использовать относительные пути: `cd data`, `cd ../scripts`, `cd -` (возврат в предыдущий каталог). Зафиксировать вывод `pwd` после каждого перехода.

3. **Операции с файлами**
   - Создать пустой файл: `touch ~/seminar02/data/empty.txt`. Проверить его существование и размер: `ls -l ~/seminar02/data/empty.txt`.
   - Записать текст в файл: `echo "Hello, Unix!" > ~/seminar02/data/hello.txt`. Прочитать содержимое: `cat ~/seminar02/data/hello.txt`.
   - Скопировать файл: `cp ~/seminar02/data/hello.txt ~/seminar02/data/hello_backup.txt`. Убедиться, что оба файла существуют и имеют одинаковое содержимое.
   - Переместить файл: `mv ~/seminar02/data/hello_backup.txt ~/seminar02/reports/`. Проверить, что файл исчез из `data/` и появился в `reports/`.
   - Переименовать файл: `mv ~/seminar02/reports/hello_backup.txt ~/seminar02/reports/report_draft.txt`.
   - Удалить файл: `rm ~/seminar02/data/empty.txt`. Объяснить в отчёте, почему `rm` не запрашивает подтверждение и чем опасен `rm -rf`.
   - Создать символическую ссылку: `ln -s ~/seminar02/data/hello.txt ~/seminar02/link_to_hello`. Вывести `ls -l ~/seminar02/link_to_hello` и объяснить разницу между символической и жёсткой ссылкой.

4. **Права доступа и владение**
   - Вывести подробный листинг файлов в `~/seminar02/data/`: `ls -la`. Объяснить в отчёте каждый столбец вывода (права, число ссылок, владелец, группа, размер, дата, имя).
   - Создать скрипт `~/seminar02/scripts/hello.sh` с содержимым:
     ```bash
     #!/bin/bash
     echo "Hello from script!"
     ```
     Попробовать запустить его: `./hello.sh`. Объяснить ошибку «Permission denied».
   - Добавить право на исполнение: `chmod +x ~/seminar02/scripts/hello.sh`. Запустить скрипт и зафиксировать вывод.
   - Установить права числовой нотацией: `chmod 640 ~/seminar02/data/hello.txt`. Объяснить, какие права получили owner, group и others. Проверить через `ls -l`.
   - Изменить владельца файла (если есть права): `chown <user>:<group> <file>`. Если прав нет — выполнить через `sudo` или описать в отчёте, что произойдёт и почему нужен root.
   - Вывести текущую маску создания файлов: `umask`. Создать новый файл и каталог, проверить их права по умолчанию, объяснить связь с umask.

5. **Перенаправление потоков и конвейеры**
   - Перенаправить stdout в файл: `ls /etc > ~/seminar02/reports/etc_listing.txt`. Просмотреть результат.
   - Дописать в файл (append): `date >> ~/seminar02/reports/etc_listing.txt`. Убедиться, что дата добавлена в конец.
   - Перенаправить stderr: запустить `ls /nonexistent 2> ~/seminar02/reports/errors.txt`. Проверить содержимое файла ошибок.
   - Объединить stdout и stderr: `ls /etc /nonexistent > ~/seminar02/reports/all_output.txt 2>&1`. Объяснить порядок перенаправлений и что означает `2>&1`.
   - Построить конвейер (pipe): `cat /etc/passwd | wc -l` — посчитать количество пользователей. Объяснить, как `|` связывает stdout одной команды со stdin другой.
   - Усложнить конвейер: `ps aux | grep bash | wc -l` — посчитать количество процессов bash. Записать результат.
   - Использовать `tee` для одновременной записи в файл и вывода на экран: `ls /etc | tee ~/seminar02/reports/etc_tee.txt | wc -l`.

6. **Переменные окружения**
   - Вывести все переменные окружения: `env` (или `printenv`). Найти и записать значения `PATH`, `HOME`, `USER`, `SHELL`, `LANG`.
   - Создать локальную переменную: `MY_VAR="seminar02"`. Убедиться, что она видна: `echo $MY_VAR`. Запустить дочерний процесс (`bash -c 'echo $MY_VAR'`) и объяснить, почему переменная не видна.
   - Экспортировать переменную: `export MY_VAR`. Повторить проверку из дочернего процесса. Зафиксировать разницу.
   - Временно задать переменную для одной команды: `GREETING="Hi" bash -c 'echo $GREETING'`. Убедиться, что после выполнения `echo $GREETING` в текущей оболочке переменная не определена.
   - Изменить `PATH`: добавить каталог `~/seminar02/scripts` в PATH: `export PATH="$HOME/seminar02/scripts:$PATH"`. Убедиться, что `hello.sh` запускается без указания пути (просто `hello.sh`).
   - Объяснить в отчёте: где хранятся переменные окружения на постоянной основе (`~/.bashrc`, `~/.profile`, `/etc/environment`), и когда они применяются.

7. **Управление процессами и задачами (jobs)**
   - Запустить долгую команду: `sleep 300`. Прервать её с помощью `Ctrl+C`. Объяснить, какой сигнал отправляется процессу.
   - Запустить `sleep 300` снова. Приостановить с помощью `Ctrl+Z`. Вывести список задач: `jobs`. Зафиксировать вывод.
   - Перевести задачу в фоновый режим: `bg %1`. Проверить статус: `jobs`. Вернуть задачу на передний план: `fg %1`. Завершить: `Ctrl+C`.
   - Запустить команду сразу в фоне: `sleep 600 &`. Вывести `jobs` и `ps` — найти PID процесса. Завершить его: `kill <PID>`.
   - Объяснить в отчёте разницу между `Ctrl+C` (SIGINT), `Ctrl+Z` (SIGTSTP) и `Ctrl+D` (EOF / завершение ввода). Описать, в каких ситуациях используется каждая комбинация.

8. **Мониторинг процессов и ресурсов**
   - Вывести список процессов текущего пользователя: `ps aux | grep $USER`. Объяснить значение столбцов: PID, %CPU, %MEM, VSZ, RSS, STAT, COMMAND.
   - Запустить `top`. Найти процесс, потребляющий больше всего CPU. Отсортировать по памяти (клавиша `M`). Выйти: `q`. Записать наблюдения.
   - Запустить `htop` (если установлен). Описать отличия от `top`: цветной вывод, дерево процессов (F5), фильтрация (F4), поиск (F3). Сделать скриншот или сохранить наблюдения.
   - Проверить наличие GPU: `nvidia-smi`. Если GPU доступен — зафиксировать модель, объём памяти, версию драйвера и CUDA. Если GPU нет — записать в отчёт и пропустить.
   - Вывести информацию о процессоре одной командой: `lscpu | head -20`. Записать количество ядер и модель.

9. **История команд и повышение продуктивности**
   - Вывести последние 20 команд: `history | tail -20`. Объяснить, где хранится история (`~/.bash_history`), и когда она записывается на диск.
   - Найти команду в истории: нажать `Ctrl+R` и начать вводить часть команды. Зафиксировать найденную команду. Повторить поиск повторным нажатием `Ctrl+R`.
   - Использовать повтор предыдущей команды: `!!`. Использовать последний аргумент предыдущей команды: `!$`. Привести примеры в отчёте.
   - Создать alias: `alias ll='ls -la'`. Проверить работу: `ll ~/seminar02`. Объяснить, как сделать alias постоянным (добавить в `~/.bashrc`).
   - Написать короткий bash-скрипт `~/seminar02/scripts/sysinfo.sh`, который:
     - выводит дату (`date`);
     - выводит имя хоста (`hostname`);
     - выводит информацию о ядре (`uname -r`);
     - выводит текущую загрузку (`uptime`);
     - выводит использование диска (`df -h /`).
     Сделать скрипт исполняемым, запустить, сохранить вывод в `~/seminar02/reports/sysinfo_output.txt`.

Отчёт и артефакты (скрипты, выводы команд, скриншоты) хранить в каталоге `~/seminar02/reports/` или в репозитории семинара по указанию преподавателя.

## Бонусные задачи

- **Bash-скрипт для резервного копирования:** написать скрипт `backup.sh`, который принимает каталог как аргумент, создаёт tar-архив с именем `backup_YYYYMMDD_HHMMSS.tar.gz` (дата генерируется автоматически через `date +%Y%m%d_%H%M%S`), сохраняет его в `~/seminar02/reports/`, выводит размер архива и количество файлов внутри. Обработать случай, когда аргумент не передан или каталог не существует (вывести сообщение об ошибке в stderr и завершиться с кодом 1).
- **Мониторинг в реальном времени:** написать bash-скрипт `monitor.sh`, который каждые 5 секунд (цикл с `sleep 5`) выводит текущее время, загрузку CPU (первая строка `top -bn1`), использование памяти (`free -h`) и количество процессов (`ps aux | wc -l`). Скрипт должен корректно завершаться по `Ctrl+C` (обработка сигнала через `trap`). Запустить в фоне, перенаправить вывод в файл, через минуту завершить и проанализировать лог.
- **Права доступа в деталях:** создать каталог `~/seminar02/shared/`, установить sticky bit (`chmod +t`), setgid (`chmod g+s`); создать в нём файлы от разных пользователей (или объяснить теоретически, если нет второго пользователя). Объяснить в отчёте, зачем нужны sticky bit и setgid на каталогах, привести реальный пример (`/tmp`).
