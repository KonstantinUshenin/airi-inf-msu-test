# Семинар 5. Unix-terminal. Настройка окружения и установка пакетов

## Цель

Научиться управлять переменными окружения, понимать механизм поиска исполняемых файлов и библиотек (`PATH`, `LD_LIBRARY_PATH`, `PYTHONPATH`), устанавливать системные и Python-пакеты разными менеджерами, создавать и использовать виртуальные окружения, а также управлять системными сервисами через systemd. Результаты фиксировать в отчёте, артефакты (скрипты, выводы команд, конфиги) сохранять на диске.

## Теоретический минимум

- **Переменные окружения:** пары ключ=значение, наследуемые дочерними процессами; `env`, `printenv`, `echo $VAR`; разница между `VAR=value` (локальная) и `export VAR=value` (экспортированная).
- **`source` (`.`):** выполнение скрипта в текущем shell (без порождения subshell); используется для загрузки конфигов (`~/.bashrc`, `activate`).
- **PATH:** список каталогов через `:`, в которых shell ищет исполняемые файлы; порядок поиска имеет значение; `which`, `type`, `command -v` для определения, какой бинарник будет запущен.
- **LD_LIBRARY_PATH:** аналог PATH для динамических библиотек (`.so`); `ldconfig -p` — кеш известных библиотек; `ldd` — зависимости бинарника.
- **PYTHONPATH:** дополнительные каталоги, в которых Python ищет модули (`sys.path`); приоритет: встроенные → PYTHONPATH → site-packages.
- **Менеджеры системных пакетов:** `apt` (Debian/Ubuntu) — репозитории, `apt update/install/remove/search`; `snap` — контейнеризованные пакеты с автообновлением.
- **Менеджеры Python-пакетов:** `pip` (классический), `uv` (быстрая замена pip + venv), `conda` (пакеты + окружения + не только Python); `pip install`, `pip freeze`, `requirements.txt`.
- **Виртуальные окружения:** изолированная копия интерпретатора и пакетов; `python -m venv`, `virtualenv`, `uv venv`, `conda create`; скрипт `activate` модифицирует `PATH` и `VIRTUAL_ENV`.
- **systemd:** система инициализации и менеджер сервисов; юниты (`.service`), `systemctl start/stop/restart/enable/status`, `journalctl` для логов.

## Задачи

1. **Переменные окружения и export**
   - Вывести все переменные окружения: `env` (или `printenv`); найти среди них `HOME`, `USER`, `SHELL`, `LANG`.
   - Создать локальную переменную: `MY_VAR="hello"`. Проверить, что она не видна дочернему процессу: `bash -c 'echo $MY_VAR'` (пустой вывод).
   - Экспортировать переменную: `export MY_VAR`. Повторить проверку — убедиться, что теперь дочерний процесс видит значение.
   - Задать переменную только для одной команды: `MY_VAR=world bash -c 'echo $MY_VAR'`; проверить, что в текущем shell значение не изменилось.
   - Записать в отчёт: в чём разница между `VAR=value`, `export VAR=value` и `VAR=value command`.

2. **source и файлы конфигурации**
   - Создать файл `myenv.sh` с содержимым:
     ```bash
     export PROJECT_NAME="seminar05"
     export PROJECT_DIR="$HOME/projects/$PROJECT_NAME"
     alias ll='ls -la'
     ```
   - Выполнить `bash myenv.sh` — проверить, что переменные в текущем shell **не** появились (`echo $PROJECT_NAME` — пусто).
   - Выполнить `source myenv.sh` (или `. myenv.sh`) — проверить, что переменные и алиас теперь доступны.
   - Объяснить в отчёте: почему `bash script.sh` запускает subshell и изменения не сохраняются, а `source` выполняет скрипт в текущем shell.
   - Посмотреть, какие файлы загружаются при старте bash: `~/.bashrc`, `~/.bash_profile`, `~/.profile`; описать в отчёте, когда какой файл читается (login vs non-login shell).

3. **PATH: поиск исполняемых файлов**
   - Вывести текущий `PATH`: `echo $PATH`; описать в отчёте, какие каталоги в нём и в каком порядке.
   - Определить, откуда запускается `python3`: `which python3`, `type python3`, `command -v python3`.
   - Создать каталог `~/bin/` и написать в нём скрипт `hello.sh` (с `#!/bin/bash` и `echo "Hello from ~/bin"`), сделать исполняемым (`chmod +x`).
   - Попробовать запустить `hello.sh` без указания пути — убедиться, что shell не находит его.
   - Добавить `~/bin` в PATH: `export PATH="$HOME/bin:$PATH"`; запустить `hello.sh` — убедиться, что теперь работает.
   - Поместить `~/bin` в конец PATH (`export PATH="$PATH:$HOME/bin"`) — объяснить в отчёте, почему порядок каталогов в PATH важен (что произойдёт, если в двух каталогах есть одноимённый бинарник).

4. **LD_LIBRARY_PATH и динамические библиотеки**
   - Вывести кеш динамических библиотек: `ldconfig -p | head -30`; найти, где находится `libc.so` и `libpthread.so`.
   - Для любого бинарника (например, `/usr/bin/python3`) вывести зависимости: `ldd /usr/bin/python3`; записать в отчёт 3-4 библиотеки и их пути.
   - Вывести текущее значение `LD_LIBRARY_PATH` (скорее всего, пустое).
   - Объяснить в отчёте: когда нужно задавать `LD_LIBRARY_PATH` (нестандартный путь к `.so`-файлам), чем это отличается от `ldconfig`, и почему злоупотреблять этой переменной опасно (конфликт версий).

5. **PYTHONPATH и sys.path**
   - Создать каталог `~/mylibs/` и в нём файл `mymodule.py`:
     ```python
     def greet():
         return "Hello from mymodule!"
     ```
   - Попробовать импортировать: `python3 -c "import mymodule"` — убедиться, что получается `ModuleNotFoundError`.
   - Задать `PYTHONPATH`: `export PYTHONPATH="$HOME/mylibs"` и повторить импорт — убедиться, что модуль найден.
   - Вывести `sys.path` из Python: `python3 -c "import sys; print('\n'.join(sys.path))"` — найти в списке `~/mylibs`.
   - Описать в отчёте порядок поиска модулей в Python и в каких случаях PYTHONPATH полезен, а в каких лучше использовать виртуальное окружение.

6. **Системные пакеты: apt и snap**
   - Обновить список пакетов: `sudo apt update`.
   - Найти пакет: `apt search tree` (или другую утилиту по выбору); установить: `sudo apt install tree`.
   - Вывести информацию о пакете: `apt show tree`; узнать, какие файлы установил пакет: `dpkg -L tree`.
   - Удалить пакет: `sudo apt remove tree`; сравнить `remove` и `purge` в отчёте.
   - Установить snap-пакет (например, `sudo snap install htop` или другой); сравнить, где он размещается (`which htop`, `snap list`).
   - Описать в отчёте: чем отличается apt от snap (зависимости, обновления, изоляция, размер).
   - *Если работаете на macOS:* использовать `brew` вместо `apt`; описать аналогии.

7. **Python-пакеты: pip, uv, conda**
   - **pip:** установить пакет в пользовательский каталог: `pip install --user httpie`; найти, куда он установился (`pip show httpie`); вывести список всех установленных пакетов: `pip list`.
   - **requirements.txt:** выполнить `pip freeze > requirements.txt`; посмотреть содержимое; установить из файла: `pip install -r requirements.txt`.
   - **uv** (если доступен): установить uv (`pip install uv` или `curl -LsSf https://astral.sh/uv/install.sh | sh`); создать окружение: `uv venv .venv`; активировать и установить пакет: `uv pip install requests`; сравнить скорость с pip.
   - **conda** (если доступен): создать окружение: `conda create -n sem05 python=3.11 -y`; активировать: `conda activate sem05`; установить пакет: `conda install numpy`; вывести список: `conda list`.
   - Записать в отчёт сравнительную таблицу: pip vs uv vs conda (скорость, возможности, когда что использовать).

8. **Виртуальные окружения**
   - Создать виртуальное окружение: `python3 -m venv ~/envs/sem05`.
   - До активации: вывести `which python3` и `echo $PATH`.
   - Активировать: `source ~/envs/sem05/bin/activate`.
   - После активации: вывести `which python3` и `echo $PATH` — описать, что изменилось.
   - Установить пакет внутри окружения: `pip install requests`; убедиться, что он доступен: `python3 -c "import requests; print(requests.__version__)"`.
   - Деактивировать: `deactivate`; убедиться, что `requests` больше не импортируется (из системного Python).
   - Прочитать скрипт `activate` (`cat ~/envs/sem05/bin/activate | head -40`) — описать в отчёте, какие переменные он модифицирует (`PATH`, `VIRTUAL_ENV`, `PS1`).
   - Объяснить в отчёте: зачем нужны виртуальные окружения (изоляция зависимостей, воспроизводимость, отсутствие конфликтов между проектами).

9. **Сервисы systemd**
   - Вывести список запущенных сервисов: `systemctl list-units --type=service --state=running`.
   - Проверить статус конкретного сервиса: `systemctl status sshd` (или `cron`, `NetworkManager` — что доступно).
   - Просмотреть логи сервиса: `journalctl -u sshd --no-pager -n 20`.
   - Просмотреть unit-файл сервиса: `systemctl cat sshd`; описать в отчёте ключевые директивы (`ExecStart`, `Restart`, `After`, `WantedBy`).
   - Создать собственный пользовательский сервис:
     - Написать простой скрипт `~/bin/myservice.sh`, который в цикле пишет дату в файл каждые 10 секунд.
     - Создать unit-файл `~/.config/systemd/user/myservice.service`:
       ```ini
       [Unit]
       Description=My test service for seminar 05

       [Service]
       ExecStart=%h/bin/myservice.sh
       Restart=on-failure

       [Install]
       WantedBy=default.target
       ```
     - Запустить: `systemctl --user daemon-reload && systemctl --user start myservice`.
     - Проверить статус: `systemctl --user status myservice`; посмотреть лог: `journalctl --user -u myservice --no-pager`.
     - Остановить: `systemctl --user stop myservice`.
   - Описать в отчёте: разницу между `systemctl start` и `systemctl enable`; что означает `Restart=on-failure`.
   - *Если systemd недоступен (macOS):* описать аналог (`launchctl`/`launchd`), показать `launchctl list` и описать формат `.plist`.

10. **Комплексное задание: скрипт настройки окружения**
    - Написать bash-скрипт `setup_env.sh`, который:
      - создаёт виртуальное окружение в заданном каталоге (путь передаётся аргументом или используется значение по умолчанию);
      - активирует окружение (через `source`);
      - устанавливает зависимости из `requirements.txt` (если файл существует);
      - добавляет `~/bin` в PATH (если ещё не добавлен);
      - экспортирует переменные `PROJECT_NAME` и `PROJECT_DIR`;
      - выводит итоговую сводку: путь к Python, версию, установленные пакеты, значения ключевых переменных.
    - Запустить скрипт через `source setup_env.sh` (объяснить, почему именно `source`, а не `bash`).
    - Сохранить скрипт и вывод в артефакты.

Отчёт и артефакты (скрипты, выводы команд, конфиги) хранить в репозитории семинара или в Jupyter-ноутбуке / на удалённом сервере по указанию преподавателя.

## Бонусные задачи

- **Свой пакет на PyPI (TestPyPI):** создать минимальный Python-пакет с `pyproject.toml`; собрать его (`python -m build`); загрузить на [TestPyPI](https://test.pypi.org/) (`twine upload --repository testpypi dist/*`); установить из TestPyPI в чистое виртуальное окружение и проверить работоспособность; описать в отчёте процесс публикации.
- **Nix или Homebrew как альтернативный менеджер пакетов:** установить `nix` (single-user mode) или `brew`; установить через него утилиту (например, `ripgrep`); сравнить подход с `apt`/`snap` — описать в отчёте плюсы и минусы (воспроизводимость, атомарные обновления, пользовательская установка без sudo).
- **LD_PRELOAD и перехват функций:** написать на C минимальную разделяемую библиотеку, которая переопределяет функцию `malloc` (или `rand`) — выводит сообщение при каждом вызове; собрать: `gcc -shared -fPIC -o mymalloc.so mymalloc.c`; запустить программу с `LD_PRELOAD=./mymalloc.so ls`; описать в отчёте, как работает `LD_PRELOAD` и почему это мощный инструмент для отладки (и потенциальная угроза безопасности).
