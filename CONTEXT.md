# Курс AIRI × ВМК МГУ — предметный глоссарий

Термины предметной области курса (лекции и семинары по Unix / информатике).
Только словарь: что термин ЕСТЬ, без деталей реализации.

## Семинар

**Семинар**:
Учебное занятие из трёх частей: микро-лекция, набор задач и разбор решений.
Хранится как каталог `seminars/NN-slug/` с файлами `demo.ipynb`, `tasks.md`, `solutions.md`.
_Avoid_: практика, урок, воркшоп

**Микро-лекция**:
Короткая (10–15 мин) демонстрация/напоминание темы в начале семинара, живущая в `demo.ipynb`.
Файл назван `demo`, а не `lecture`, чтобы не путать её с настоящими лекциями курса в `lectures/`.
Начинается с мотивации и содержит по ходу вопросы для коммуникации со студентами.
_Avoid_: мини-лекция, вводная, теория

**Мотивация**:
Обязательный вводный блок микро-лекции, объясняющий студентам, почему и зачем нужна тема.
_Avoid_: введение, обоснование, intro

**Вопрос для коммуникации**:
Встроенный в микро-лекцию вопрос к аудитории, оформленный блоком `#### ❓ **Вопрос**` со свёрнутым ответом в `<details>`.
Служит для диалога со студентами, а не для оценивания.
_Avoid_: контрольный вопрос, discussion question

**Задача**:
Практическое упражнение семинара, решаемое в консоли или Jupyter; формулировка в `tasks.md`, решение в `solutions.md`.
_Avoid_: упражнение, задание, problem

**Уровень задачи**:
Категория сложности задачи: одна из «база», «среднее», «сложное».
_Avoid_: сложность, tier, Basic/Advanced

**Тестовый пример**:
Прикреплённая к формулировке задачи пара «входные аргументы → ожидаемый результат» (или аналог, если задача не про скрипт), по которой студент проверяет решение.
_Avoid_: тест-кейс, пример вывода, sample

**Защита семинара**:
Процедура, в которой студент отвечает семинаристу по сделанным задачам; часть вопросов — теор-минимум.
_Avoid_: сдача, приёмка, defense

**Теор-минимум**:
Обязательные вопросы на защите, без ответа на которые результат нельзя было получить; провал → 0 баллов за работу.
_Avoid_: обязательные вопросы, базовые вопросы

## Пятиминутка

**Пятиминутка**:
Короткий квиз сразу после лекции: несколько вопросов по слайдам именно этой лекции,
проходится студентами с телефона в аудитории за фиксированное время.
Служит проверкой того, что лекция услышана, а не итоговым оцениванием.
_Avoid_: квиз, тест, контрольная, опрос

**Билет**:
Одноразовый анонимный код входа в пятиминутку, напечатанный QR-кодом и розданный
в аудитории. Личности сам по себе не несёт: ФИО приходит отдельно из SSO, а билет
доказывает, что человек физически был на лекции. Один билет — одна попытка.
_Avoid_: токен, приглашение, код студента, персональная ссылка

**Банк вопросов**:
Все вопросы, написанные по слайдам одной лекции (порядка сорока с вариантами ответа
и десяти открытых), из которых каждому студенту достаётся небольшая выборка.
Единственная форма, в которой вопросы существуют заранее: персональных наборов
на диске нет, выборка происходит в момент входа.
Хранится markdown-файлом рядом с лекциями и правится людьми через pull request.
_Avoid_: пул вопросов, база вопросов, набор вопросов

**Набор**:
Выборка из банка, доставшаяся одному студенту на одну попытку: четыре вопроса
с вариантами и один открытый. Определяется парой «лекция + логин» и потому
не меняется при перезагрузке страницы, но у соседа другой.
_Avoid_: вариант, билет (билет — это код входа), персональный набор

**Попытка**:
Один проход пятиминутки одним студентом: пара «билет + личность из SSO», выданный
набор, ответы с временем на каждый и итоговый разбор. Единица, которую видит
преподаватель в таблице и по которой считается вся аналитика.
_Avoid_: сессия, прохождение, сдача

**Открытый вопрос**:
Единственный вопрос набора без вариантов ответа, оценивается сравнением с эталоном
из банка, а не точным совпадением строки. Вердикт по нему появляется позже самого
разбора, поэтому у попытки он может отсутствовать.
_Avoid_: свободный ответ, эссе, текстовый вопрос
